# Binder gauntlet: validate and profile designed binders before anyone orders DNA

A structure predictor's interface confidence is the field's standard first filter, and it is only that. This skill is the rest of the computational diligence a protein-engineering or pharma team expects to see next to a table of designed binders: (A) evidence the binding claim survives checks the design loop did not optimise against, with controls; (B) a developability profile of each design; (C) an honest dossier that says what was not checked. It is target-agnostic and tool-agnostic — use whatever predictors and utilities are installed — but names common open tools and literature thresholds (see references/thresholds.md). Budget it explicitly: time one complex prediction per predictor and multiply — A1 for 30 designs × 2 predictors × 3 seeds is ≈180 complex predictions plus the monomer refolds and controls; A6–A9 on 10 leads roughly doubles that; part B is CPU-minutes.

## Before you start

- **Script:** `${CLAUDE_SKILL_DIR}/scripts/sequence_profile.py` (standard library only) turns one or many sequences (a FASTA file, or `--seq`) into Part B's sequence-level table: size, pI and net charge, GRAVY, A280 measurability, cysteines, liability motifs with their positions, hydrophobic and charged windows, candidate protease sites; one row per design, CSV or `--json`. Run it on the shortlist every round instead of re-deriving the motif rules. First use in a new environment: `python3 "${CLAUDE_SKILL_DIR}/scripts/sequence_profile.py" --self-test` should end "self-test passed".
- **Where to write:** a working folder in the user's directory, for example `gauntlet/<target>/` with one sub-folder per round. Never write into the skill's folder.
- **References:** `references/thresholds.md` (where every pass mark comes from), `references/developability-checks.md` (how to compute each Part B item), `references/dossier-template.md` (Part C), `references/honest-limits.md` (the sentences to use).
- **On a cluster:** where GPU work is dispatched as Kubernetes or Slurm jobs rather than run in the session, every structure-prediction run in Part A (complex re-predictions, monomer refolds, co-folds, the controls included) goes out as a batch job the way the session submits its other GPU work; Part B, the superpositions and the write-up stay in the session.

## Principles
1. **Independence.** A check only adds evidence if the design loop did not optimise against it. Prefer predictors, seeds and physics terms outside your objective; say which checks are and are not independent.
2. **Same pipeline for controls and designs.** Every validation protocol is first run on positive and negative controls; report their numbers beside the designs'. A pipeline that cannot separate a known binder from a scrambled sequence is not evidence.
3. **Not run ≠ passed.** Anything you did not check is listed as not checked, with the reason.
4. **Pass/fail only where the literature gives a threshold; otherwise report values against references.** There is no validated computational developability gauntlet for miniproteins (antibody rules such as TAP do not transfer); show descriptors, compare to reference proteins if available, do not invent cut-offs.
5. **Reject in the open.** Candidates dropped on this evidence are part of the deliverable, with the reason.

## Run it in the loop, not only at the end
These checks are for steering design, not just for documenting it. At every selection or refinement round, run the cheap ones on the current shortlist and use the results to decide what to keep, drop, mutate or redesign: sequence liabilities (above all labile motifs inside the interface), A280 measurability, pI and charge patches, hydrophobic patch on the free (non-interface) face, low-complexity or poly-residue runs, a self-association co-fold, designability/sequence recovery (A8, B1–B4, B7, B8 — minutes per round), plus an out-of-objective re-prediction with pose agreement, a monomer refold and the partner-superposition blocker test on the current top N (A1, A2, A5 — N × predictors × seeds complex predictions; time it as in the budget note above). Reserve the expensive checks — the full paralog/ortholog/decoy panel (A6), binding-dead mutants (A7), full-length-target refolds (A9), any MD (A10) — for leads before the final pick. Run the controls (A3) early, and again through each protocol the first time you use it, so every later number has a reference. Keep a running "set aside, and why" log from the first round; it becomes dossier topic 8. A liability found in a final candidate costs a redesign or a caveat; the same liability found at round one costs nothing. The dossier is the record of this steering, not the goal. One trade-off to manage (Principle 1): a predictor you select on joins your objective, so state the A4 rule before the first round, hold at least one predictor or protocol back for the final pass, and say in dossier topic 1 which checks steered selection and which stayed independent.

## Part A — Binding-validation gauntlet (per design unless noted)
A1. **Out-of-objective re-prediction and pose agreement.** Re-predict each binder–target complex from sequence with at least one predictor not used in design or scoring — two if you have them — (e.g. AF2-multimer with target template ± initial guess, Boltz, Chai, Protenix/AF3-class, or single-sequence predictors where they support complexes), several seeds each. Record interface confidence (ipTM, interface pAE, ipSAE) and agreement with YOUR designed pose (DockQ, interface RMSD, binder RMSD after target superposition). Literature pass marks: interface pAE < 10; DockQ ≥ 0.49 "medium", ≥ 0.23 "acceptable"; binder Cα RMSD to design ≲ 2 Å (the pAE < 10 mark is calibrated for AF2 initial-guess; for other predictors report the value beside the controls' values rather than applying 10 as a pass line). A confident prediction in a different pose is a failure, not a pass. If only one independent predictor is available, run it with more seeds and label section 1 "single-predictor"; if none is, say so and report A2/A3/A5/A9 with the design-time predictor, marked not independent.
A2. **Monomer refold.** Fold the binder alone (no target); require high pLDDT (> 80) and RMSD to the designed monomer ≲ 1–2 Å (≤ 3.5 Å bound-vs-unbound is BindCraft's filter). Flag fold-on-binding designs explicitly.
A3. **Controls through the identical protocol.** Positives: a natural partner or known binder of the target extracted from a deposited complex if one exists (and an engineered high-affinity variant if public). Negatives: composition-preserving scrambles of several designs; a well-folded unrelated protein of similar size; and a *decoy target* (fold designs against an unrelated protein of the same fold class as the target). Report the score distributions and where each design falls; a design that scores with the negatives fails this check.
A4. **Consensus rule.** State a rule before looking (e.g. "every independent predictor you ran — at least one, held back from selection — reproduces the designed pose at DockQ ≥ 0.49 and its interface confidence is in the range of the positive controls") and apply it uniformly; note that once used for selection it is no longer an independent check.
A5. **Function/epitope test by superposition.** Superpose the natural partner's complex onto each predicted design complex; report steric clash with the partner and fraction of the partner's footprint covered → "predicted blocker: yes/no". Footprint overlap alone is weaker than clash.
A6. **Specificity and cross-reactivity panel** (when sequences are available or can be staged): co-fold each design against the target's closest human paralogs and same-family domains and 1–2 unrelated same-fold decoys (want low confidence), and against mouse/cynomolgus orthologs (cross-reactivity is usually WANTED for animal models — report it as such). Co-folding confidence discriminates on/off-target only roughly; say so.
A7. **Binding-dead control mutants.** For the top designs, propose 2–3-residue hotspot knockouts or charge reversals at the designed interface and re-predict; expect confidence/pose to collapse. Single-Ala changes rarely move co-folding scores — do not present this as a ΔΔG scan (that needs Rosetta/FoldX). Output: a named binding-dead mutant per lead for the lab.
A8. **Self-association.** Co-fold two copies of each binder; a confident homodimer, especially one burying the binding face, is a flag (designed binders have turned out dimeric by SEC-MALS).
A9. **Native-context checks.** From the target's UniProt entry: N-glycosylation sequons and annotated glycosites, disulfides, natural variants and isoform boundaries near the footprint — a design made against a bare, truncated crystal construct can target a surface that is glycan-covered or absent on the cell. Re-predict leads against the full extracellular region (or full domain architecture), not just the truncated construct you designed against, and check approach direction relative to the membrane/other domains.
A10. **Pose persistence.** Across seeds, predictors and (optionally) short MD, report interface-contact persistence and pose RMSD spread; treat MD as a red-flag screen only — there is no published evidence we know of that it raises hit rates beyond A1-type filters.
A11. **Physics-lite interface metrics** (label uncalibrated if no Rosetta/FoldX): buried SASA, shape complementarity, interface H-bonds/salt bridges, buried unsatisfied polar atoms, interface hydrophobic fraction.

## Part B — Developability profile (CPU; per design)
See references/developability-checks.md for motif lists and how to compute each item with biopython/freesasa/DSSP.
B1. Chemical liabilities with solvent exposure and interface membership: deamidation (NG ≫ NS > NT/NN), Asp isomerisation (DG, DS), Asp-Pro, exposed Met/Trp (oxidation), N-X-S/T sequons, free Cys, N-terminal Gln.
B2. Charge: pI, net charge at pH 7.4, largest positive and negative surface patches; interface His count (pH sensitivity).
B3. Hydrophobic surface: largest hydrophobic patch and a SAP-like score, reported separately for the binding face and the rest of the surface (the interface may be hydrophobic; the free surface should not be).
B4. Aggregation-prone stretches (sliding-window hydrophobicity/β-propensity heuristic; a dedicated predictor such as Aggrescan3D/CamSol/TANGO if installed and licensed where required) and low-complexity/poly-ion runs.
B5. Protease exposure: canonical trypsin/chymotrypsin/Asp-N sites that sit in loops with high SASA.
B6. Stability proxies: monomer pLDDT, design-vs-refold RMSD, inverse-folding/LM log-likelihood, helix capping/buried polar sanity; note de novo miniproteins are typically hyperstable (Tm > 70–90 °C) so this is a sanity check, not a ranking.
B7. Designability: sequence recovery of the designed backbone by an inverse-folding model and how many alternative sequences refold to it.
B8. Format and manufacturability: which terminus is solvent-exposed and ≥ 15–20 Å from the interface (tag / Fc / albumin-binder attachment); expression host implied (Cys-free, no glycosylation → E. coli); A280 measurability (Trp/Tyr present?); gene-synthesis complexity of a codon-optimised gene (GC%, repeats, homopolymers); intended therapeutic/imaging format and its PK implication — an unmodified protein < 30–50 kDa is renally filtered (half-life of order minutes–hours); half-life comes from format (Fc, albumin binding, PEG/polypeptide fusion), not sequence. Do not report a "predicted PK" beyond this.
B9. Immunogenicity: if an HLA-II epitope predictor is available, report predicted epitope density vs reference proteins; otherwise list it under "not checked". "Humanness" is undefined for de novo sequences; aggregation and epitope content are the computable levers; the real assessment is in vitro.
B10. What must go to the lab regardless: expression/solubility/SEC, affinity and kinetics, specificity panel, Tm, protease/serum stability, structure of the complex, in-vitro immunogenicity, any PK.

## Part C — Reporting
Write a markdown dossier covering these nine topics (template: references/dossier-template.md): (1) binding evidence beyond the objective + controls + consensus call; (2) function/blocker; (3) specificity and species cross-reactivity; (4) robustness (pose persistence, self-association, refold-alone; binding-dead mutants for leads); (5) native context; (6) developability per design; (7) interface metrics (uncalibrated); (8) candidates set aside and why; (9) not checked and why. Plus one per-design CSV keyed by the binder sequence, so rows can be joined to whatever table lists the designs. Use the limits language in references/honest-limits.md verbatim or close to it: co-folding models share training data, so agreement is correlated evidence; controls show the pipeline is not trivially fooled, not that designs bind; confidence filters raise lab hit rates but do not predict affinity; developability descriptors are shown against references, not as pass/fail.

## Order of work when time is short
Controls first (A3), and through each new protocol as it is introduced → at each design round: B1–B4, B7, B8 and A8 on the shortlist (minutes) plus A1/A2/A5 on the current top N, dropping or redesigning on the results → before the final pick: complete A1/A2 on everything still kept (including the predictor held back from selection) and apply the A4 rule, then A9 and A6/A7 on the leads → the remaining items (A10, A11, B5, B6, B9) → write up, always leaving time for topic (9). If you only discover this skill at the end, run it in the listed order on the final set and say in the dossier that it was applied post hoc.
